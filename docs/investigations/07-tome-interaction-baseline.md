# Investigation 07 — Tome interaction baseline

## Schema 5 and historical evidence

The schema 5 DLL uses the existing activation and inventory sinks and adds BookMenu open/close and `SpellsLearned::Event` notifications. These events describe observed boundaries. BookMenu opening does not establish a call to `TESObjectBOOK::Read`, and the spell notification has no spell payload. Schema 5 had no direct Read entry/exit probe. The observer forwards all notifications. [CommonLib spell notification](https://github.com/alandtse/CommonLibSSE-NG/blob/9955ae3b18dd0aedbebb58fa207a4b7180eb6d67/include/RE/S/SpellsLearned.h)

The preserved 1.7.104 schema 5 launch log shows runtime preflight, observer registration, a verified input thread and save-load markers. It does not contain a read trial or establish gameplay outcomes.

## Schema 6 source audit (Task 08B)

The current source adds an opt-in forward-only probe at three call sites, installed at PostPostLoad only when an `UntamedTomes.TraceRead` file exists in the SKSE log directory. It is gated to 1.7.104, checks the relocated Read address against RVA `280290`, hashes `0x249` bytes of its body, checks the five original bytes at each call site, and refuses installation if any of four named competing modules is already loaded. This list cannot detect every conflicting mod or a later patch. The installed executable's file bytes were checked offline: the body hash matches `A0B7B66E2B2D53F0`, and calls at `9074F8`, `91382E` and `945D97` contain the expected bytes and each target `280290`. File bytes do not establish live relocation, ABI, caller coverage or absence of runtime patches.

For a teaching book the wrapper logs book, linked spell and reader FormIDs, thread, call-site RVA and a paired entry/exit sequence. It calls the original once and returns its result unchanged. Other books call the original once without read-probe rows. `known_before` and `known_after` are sampled only when the reader is the player on the previously verified input thread; `-1` means unavailable, not unknown spell. The decision helper is hardcoded to unavailable and has no gameplay effect. These are source-level observations, not runtime proof. Thread safety, live argument identity, call order, return semantics, all reading paths and compatibility remain unverified.

No read hook should be added without validating its specific uncovered path, ABI and conflicts.

## Task 08D — world interaction control and entry-hook investigation

The installed Read Or Take SKSE is MO2 version 1.5.1 (DLL file version `1.5.1.1.0`, SHA-256 `5037F69E3E9A0A9CB18A19E6C1F3835BC061227604BE5C6B58C2938BA`). Its mod directory contains a DLL, PDB and INI, no ESP or Papyrus scripts. The INI selects automatic default action and enables automatic use of spell tomes. The published [Read Or Take source](https://github.com/powerof3/ReadOrTakeBooks/blob/master/src/Hooks.cpp) replaces the book activation vfunc. Its spell-tome READ branch calls `PickUpObject`, then `TESObjectBOOK::Read(actor)`, then removes one copy if Read returns true; TAKE picks up without that read call. Its ordinary-book READ opens BookMenu. This is source-level evidence, not proof that the installed DLL was built from this exact revision. A call originating in that DLL would bypass our three patched Skyrim call sites, a plausible explanation for the 08C observation, not yet a captured call stack.

On 14 November the same schema 6 DLL was launched through MO2 with Read Or Take unchecked. SKSE's launch log did not list its DLL; the native log confirmed runtime 1.7.104 and probe ready. The user reported world activation took the Firebolt tome without learning; Papyrus rejected it. After a reload, the user disabled Untamed Tomes, spawned a Firebolt tome into inventory, enabled Untamed Tomes and used it: the player learned the spell. The latter produced an entry/exit at `945D97`, player `00000014`, Firebolt `000A26FD` / `00012FD0`, known 0 → 1, return true, then an outbound event. This is an inventory control, not direct world READ. The world TAKE produced no read entry or learning event and an outbound event about 1.05 seconds after inbound, consistent with Papyrus removal. The native and Papyrus logs are preserved in the native checkout under `task08d-preservation/control-native.log` and `control-papyrus.log`.

The user confirmed the placed tome immediately took without a book menu in this control. **Coverage blocker:** this run did not demonstrate an in-place vanilla world READ and does not establish whether another untested vanilla path exists. The direct Read Or Take world path is strongly supported by published source and the prior user-reported READ, but its installed DLL's actual call and engine target are not independently traced. Existing inventory and Take observations are unchanged; no new forward-only hook or new gameplay logic was installed in 08D. The probe marker was removed after the control; Read Or Take was left disabled in the MO2 Default profile because computer use was stopped before it could be restored.

The local CommonLib wrapper resolves nonvirtual `Read` with `RELOCATION_ID(17439, 17842)` and the observed inventory call validates its book/reader arguments for that path. [Lodestone's entry detour](https://github.com/pprarj/lodestone/blob/main/src/Core/SpellTomes.cpp) uses the same relocation, a SafetyHook trampoline and passthrough with no registrants; its source warns a chained hook can make the apparent original another plugin's thunk. An entry detour is a promising shared seam, but current evidence does not validate its displaced instructions, coexistence with schema 6 call-site hooks, install order, other detours, or the installed Read Or Take caller on 1.7.104. Existing schema 6 calls the raw target address, so stacking both probes naively can double-log or change chaining. Do not add the entry patch until a mutually exclusive, guarded forwarding design and actual caller/return behavior can be validated. No hook on 1.6.1170 is authorized by this evidence.

Task 08C rebuilt and deployed the DLL and PDB using xmake; deployed hashes matched the build (`A478D224F573EF2C142FFD267FEBC2BFDA331CBDF069E7D22DBC25079BC7AF85` for the DLL). The schema 6 DLL and PDB remain deployed. The preceding schema 5 files and schema 6 files are preserved in `task08c-preservation`; the prior deployment was also backed up in `task08b-preservation`. The temporary `UntamedTomes.TraceRead` marker was removed after the trials. A running game retains already-installed hooks until it exits; subsequent launches do not enable the probe without the marker.

Task 08B built schema 6 successfully on 14 November 2026, but did not launch Skyrim: Mod Organizer was locked by an existing xEdit session. All five runtime trials, hook installation and gameplay outcomes therefore remain pending. The temporary marker was removed and the previous deployed DLL and PDB restored. The schema 6 DLL remains in the native build directory. The previous DLL, PDB and schema 5 log were copied to the native `task08b-preservation` directory before the build; an existing Papyrus log was copied there when present. These are local preservation artifacts, not source files to commit.

The CommonLib checkout was inspected without reset: its worktree is clean at `9955ae3b18dd0aedbebb58fa207a4b7180eb6d67` (v16.4.0), whereas the native parent HEAD records `b9f1e9b4e4b102f95bb63590b0b31542c5d49747`. Review and record the submodule pointer with the native changes when committing. The Papyrus repository's documentation allowlist previously omitted investigations 04–07, the protection catalogue and the MCM audit; these recovered documents are now visible to Git. Build caches, PEX files and local settings remain ignored.

Before any synchronous protection decision, establish the live call sites, ABI and thread context, a safe source of current policy, and reliable identity or an explicit ambiguity policy for a handled copy. The existing inventory observer cannot establish same-copy identity or reliably run at the read boundary. Determine conflict behavior beyond the four named module checks and verify each runtime independently; the schema 6 hook must stay disabled on 1.6.1170.

## Export verification

The 1.7.104 developer launch exported 158 records from 14 originating plugins. The set includes Skyrim.esm, DLC and 47 Creation records, including 16 from Arcane Accessories. Conventional third-party records use the same teaching-link path. This load order did not supply a separate third-party spell-pack fixture. The export assigned primary-effect confidence to 154 records and left four unresolved.

- Firebolt, `Skyrim.esm:0A26FD`, resolved to Destruction / Apprentice using primary effect `012F03` and skill 25. Impact stagger and fear remained in the secondary list.
- Dead Thrall, `Skyrim.esm:0A26F9`, resolved to Conjuration / Master using primary effect `07E8E0` and skill 100. Its zero-minimum secondary effect produced a warning without changing the tier.
