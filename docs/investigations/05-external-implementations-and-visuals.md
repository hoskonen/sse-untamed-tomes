## Observer timing on Skyrim 1.7.104

The schema-3 log captured the eight player inventory notifications from 16:21:01.402 through 16:21:10.285. The first pending input callback reported a mismatch, with callback thread 6268 versus window owner and engine main thread 21512. A failed check leaves the FIFO untouched. The diagnostic is emitted once, so it cannot show how often subsequent input dispatch was missing or ran on an ineligible thread. At 16:21:39.369 the verified thread 21512 processed all eight rows in about 0.23 ms between the first and last log lines. At drain time all rows had `console=1` and `paused=1`. The trace cannot prove that opening the console caused the thread change.

The same-session Papyrus trace identifies the four FormIDs and brackets removal in the matching capture interval at its one-second wall-clock precision. The logged Papyrus removal call brackets span 63–66 ms in the script's application clock. The observer delay measures when it got an eligible callback, rather than how long pickup or removal took. Input-to-pickup time was not measured.

All eight rows resolved BOOK and spell metadata. Each inbound row supplied source ID zero and no world handle. Resolving the player endpoint on the outbound rows cannot recover a missing source. Sampled menu state, cell, location and any ownership are current at resolution and may differ from the transaction. Even prompt resolution of a reference owner would not establish per-stack ownership or authorization. Keep `acquisition=unknown`. BarterMenu and vendor context alone cannot verify a purchase. The queue remains useful for metadata and ordering diagnostics and is unsuitable as a real-time reaction trigger. The implementation is in the C++ project under `src/main.cpp`.

## Placed-book effects

The local Creation Kit script declarations expose native EffectShader, impact, sound and physics calls. I also read the local game's `Skyrim.esm` record headers to confirm the EditorIDs and FormIDs below. Their presence establishes that the records can be selected for a test. Visibility, audio mix and physics response on a particular book still require an in-game probe.

## First visible prototype

In a disposable test cell or save, use an explicit debug trigger on one loaded, unmodified placed vanilla tome. Re-resolve its reference at the verified test boundary and play a short vanilla EFSH pulse, around half a second, while it stays in the world. Repeat on a mod-added tome and its winning mesh, then repeat after reloading the cell. Compare a control without the effect and test a disabled or unloaded target to confirm it is skipped. Record the target FormID, chosen EFSH and whether the effect appears and ends cleanly. Add one quiet spatial cue only after the shader test succeeds. Keep impact and Havok as independent later probes.

This isolates rendering and lifetime from pickup cancellation. For a later activation-triggered reaction, first establish exactly which engine call still owns the placed reference, which thread runs it and whether the effect needs the reference to remain in the world after return. Verify on both 1.7.104 and 1.6.1170 with competing book or menu hooks disabled for the baseline. A visual that survives the controlled placed-book test still needs a separate real-pickup test. No runtime effect or gameplay change was made in this investigation.
